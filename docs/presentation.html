Component 1: CAP Service

🎯 Node.js CAP Application

  • OData API for task management and reservation
  • Custom Metric Reporter (every 60 seconds)
  • mTLS Authentication with Application Autoscaler
  • Task Queue Logic (NEW → PROCESSING → COMPLETED)
📈 Custom Metric:
taskqueue = COUNT(Tasks WHERE status = 'NEW')

CAP: Metric Reporting

// Every 60 seconds
cds.spawn({ every: 60000 }, async () => {
  const openTasks = await SELECT.one
    .from(Tasks)
    .where({ status: "NEW" })
    .columns("count(*) as count");

  await axios.post(
    `${mtlsUrl}/v1/apps/${appId}/metrics`,
    {
      instance_index: 0,
      metrics: [{
        name: "taskqueue",
        value: openTasks.count
      }]
    },
    { httpsAgent: mtlsAgent }
  );
});

CAP: Task Reservation API

this.on(reserveOpenTask, async (req) => {
  const nextTask = await SELECT.one
    .from(Tasks)
    .where({ status: "NEW" })
    .orderBy("createdAt ASC")
    .forUpdate();
    
  if (nextTask) {
    await UPDATE(Tasks, nextTask.ID).set({
      status: "PROCESSING",
      processingInstance: req.data.instanceIndex
    });
    return { ID: nextTask.ID, name: nextTask.name };
  }
  return null;
});

Component 2: .NET Worker Service

⚙️ ASP.NET Core Background Service

  • Background Worker polling for tasks
  • HTTP Client calling CAP OData API
  • OAuth 2.0 Client Credentials authentication
  • Graceful Shutdown handling for task cancellation
🔄 Polling Loop: Fetches next task → Processes → Marks complete → Repeats

.NET: Background Service

protected override async Task ExecuteAsync(
    CancellationToken stoppingToken) {
  
  while (!stoppingToken.IsCancellationRequested) {
    var processor = scope.ServiceProvider
      .GetRequiredService<ITaskProcessor>();
    
    if (await processor.ProcessTaskAsync(stoppingToken) == 0) {
      _logger.LogInformation("No tasks. Waiting...");
      await Task.Delay(TimeSpan.FromSeconds(30), 
                       stoppingToken);
    }
  }
}

.NET: Task Processing

public async Task<int> ProcessTaskAsync(CancellationToken ct) {
  // 1. Reserve next task via CAP API
  var task = await FetchNextOpenTaskAsync(ct);
  
  if (task?.ID != null) {
    _logger.LogInformation("Processing Task: {taskId}", task.ID);
    
    // 2. Simulate work
    var delay = task.Delay ?? Random.Shared.Next(30, 101);
    await Task.Delay(TimeSpan.FromSeconds(delay), ct);
    
    // 3. Mark complete
    await SetTaskCompleted(task.ID, ct);
    return 1;
  }
  return 0;
}

Component 3: Application Autoscaler

📊 SAP Application Autoscaler

  • Custom Metric Collection via mTLS endpoint
  • Scaling Policies based on queue depth
  • Dynamic Instance Management (1 to N workers)
  • Cool-down Periods to prevent flapping
⚡ Scaling Logic:
  • taskqueue > 3 → Scale UP
  • taskqueue ≤ 3 → Scale DOWN

Component 4: Fiori Elements App

🖥️ Task Management UI

🎮 Demo Interface: Create tasks to trigger auto-scaling behavior

End-to-End Flow

  1. 👤 User creates tasks via Fiori UI
  2. 💾 Tasks stored in HANA Cloud with status "NEW"
  3. 📊 CAP Service reports queue size to Autoscaler every 60s
  4. ⚖️ Autoscaler evaluates metric against policies
  5. 🚀 Autoscaler scales .NET instances up or down
  6. 🔄 .NET Workers poll CAP API for tasks
  7. 🔒 Task status updated: NEW → PROCESSING
  8. ⏳ Worker processes task (simulated delay)
  9. ✅ Task status updated: PROCESSING → COMPLETED
  10. 🔁 Loop continues with next task

Challenges & Considerations

⚠️ Graceful Shutdown
Instances may be terminated while processing tasks. Need proper cancellation handling.
⏱️ Metric Reporting Frequency
60-second reporting interval trades off between responsiveness and overhead.
🔐 Certificate Rotation
mTLS certificates renewed every 24 hours, must reload on each request.

Future Enhancements

  • ✨ Intelligent downscaling: Prevent instance termination during task processing
  • 📊 Task prioritization: Process high-priority tasks first
  • 🔄 Retry logic: Automatic retry for failed tasks
  • 📈 Multi-metric scaling: Combine queue depth with CPU/memory
  • 🔔 Alerting: Notify on queue overflow or processing failures
